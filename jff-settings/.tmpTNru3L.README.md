# jff settings

A GTK4 / libadwaita app that edits jff's `config.kdl`. It looks and behaves like GNOME's
Settings: a sidebar with search on the left, preference pages on the right, and a single
column layout when the window gets narrow. It lives outside `src/` with its own workspace, so
the compositor gains no GTK dependency and `cargo build --release` at the repo root is
unchanged.

```
cd jff-settings
cargo run --release -p jff-settings
```

Needs the development packages of GTK 4.10 or newer and libadwaita 1.4 or newer.

## How it works

- Edits the one file jff reads: `$JFF_CONFIG`, then `$XDG_CONFIG_HOME/jff/config.kdl`,
  then `~/.config/jff/config.kdl`. If there is none, the first change creates it from jff's
  built-in defaults.
- Comments and formatting of everything it doesn't touch are kept.
- Each change is saved half a second after the last one. The save is checked with
  `jff check-config FILE`; if jff refuses it, the old file is put back and a message says why.
  jff watches the file, so a good save applies at once.
- The first save of a session copies an existing file to `config.kdl.bak`.
- If `jff` is not on `PATH`, the check is skipped.
- Settings that only exist by being written (blur, the workspace wall, the border) are
  switched on and off from their first row, and the rows below are greyed out while they are off.
  That way editing a detail never turns a feature on by accident.
- Search (`Ctrl+F`, or just start typing) filters the sidebar by page and by the names of the
  settings on it. Enter opens the first match.
- The main menu opens the config file in your default editor and has the About window.

## Pages

| Page | Settings |
| --- | --- |
| Appearance | gaps, corner radius, popup radius, server-side decorations, border (width, colors, animation), on-screen display |
| Effects | blur (with its lists), window animations |
| Multitasking | workspaces (count, per display), maximize new windows, drag modifier, hot corner, window switcher, overview, workspace wall |
| Displays | one entry per output: off, position, mode, variable refresh rate, HDR, ICC profile, game hint, color management; then global color management and tearing |
| Keyboard | layout, variant, options, rules, model, repeat delay and rate, Num Lock, global hotkeys |
| Keyboard Shortcuts | add, edit and remove bindings; every action jff knows, with its arguments |
| Window Rules | add, edit, reorder and remove rules: match (app id, title, tag, dialog, restored) and actions |
| Startup Applications | `autostart` and `sh-autostart` lines |
| System | screenshots, logging |

## Limits

- A window rule with several `match` lines shows the first; the others are kept as they are.
- A key combination can only use letters, digits and `+ _ - .` (symbols by name: `comma`).
- If jff refuses a change, the file goes back, but the value stays in the window and later
  saves fail the same way until you fix it. The message says what jff did not like.

## Adding a setting

Add a `Field` to `crates/jff-settings/src/pages.rs`. Use only keys jff knows: an unknown key
inside a known block is an error for jff. Row titles are Title Case, subtitles are sentence
case without a final period, like the GNOME HIG asks.
